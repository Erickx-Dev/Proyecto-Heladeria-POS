## 4. Impacto en Esquema de Persistencia y Base de Datos

- **¿Hubo alteraciones al modelo de datos en esta sesión?:** SÍ
- **Archivos de Persistencia Afectados:**
  - `database/schema.sql`: MODIFICADO
  - `database/migrations.py`: SIN CAMBIOS *(esquema compatible con el motor de migraciones)*
  - `data/heladeria.db`: REGENERADO

### Detalle de Modificaciones DDL / DML
- **Tabla Modificada:** `Usuario`
- **Cambio en Restricción:**
  ```sql
  -- DDL Modificado en Usuario
  CREATE TABLE IF NOT EXISTS Usuario (
      id_usuario INTEGER PRIMARY KEY AUTOINCREMENT,
      nombre TEXT NOT NULL CHECK (length(trim(nombre)) > 0),
      username TEXT NOT NULL UNIQUE CHECK (length(trim(username)) >= 3),
      password_hash TEXT NOT NULL CHECK (length(password_hash) = 60), -- bcrypt
      id_rol INTEGER NOT NULL,
      estado INTEGER NOT NULL DEFAULT 1 CHECK (estado IN (0, 1)),
      FOREIGN KEY (id_rol) REFERENCES Rol (id_rol) ON DELETE RESTRICT ON UPDATE CASCADE
  );
  ```
- **Razón Técnica del Cambio:** Cumplimiento de estándares de seguridad OWASP/NIST. SHA-256 es una función de hash rápida y vulnerable a aceleradores GPU en ataques offline. `bcrypt` incorpora sal automática por diseño y coste configurable de iteraciones para ralentizar ataques de fuerza bruta.

### Procedimiento de Migración / Verificación Local
1. Asegurar la presencia de la librería `bcrypt` en el entorno Python local:
   ```powershell
   python -m pip install bcrypt
   ```
2. Re-inicializar el esquema relacional en caliente:
   ```powershell
   python -c "from database.migrations import inicializar_base_de_datos; inicializar_base_de_datos(forzar=True)"
   ```
3. Ejecutar las pruebas unitarias para certificar consistencia:
   ```powershell
   python -m unittest tests/test_database.py -v
   ```
